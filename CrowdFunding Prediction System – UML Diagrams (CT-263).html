CrowdFunding Campaign Success Prediction System

CT-263 OOAD · CCA / CCP · All 8 UML diagrams drawn in the notation from the Week 4, 5 and 6 slides. Scroll sideways on a phone for the wide ones.

1. Use-Case Diagram

Notation (Week 4): stick-figure actors outside the system boundary, ovals inside, association = plain line, «include» / «extend» = dashed open arrows, generalization = hollow triangle (three training variants specialise Train / Retrain Model).

2. Activity Diagram

Notation (Week 4): initial node, rounded actions, object nodes with dashed object flow, decision and merge diamonds with [guards], fork and join bars, three swimlanes, final node.

3. Class Diagram

Notation (Week 5): three-part boxes, visibility + / - , italic abstract names, underlined static members, association with multiplicity, hollow diamond = aggregation, filled diamond = composition, hollow triangle = generalization / realization. Design patterns: Strategy (Predictor), Factory (ModelFactory), Singleton (ModelRegistry), Observer (PredictionObserver).

4. Object Diagram

Notation (Week 5): same box as a class diagram, but the name is underlined (object : Class) and attributes hold real values. A snapshot of one prediction request.

5. Component Diagram

Notation (Week 5): «component» boxes with the plug icon, ports (small squares) on the system boundary, provided interface = ball (circle), required interface = socket (half-circle), ball-in-socket = assembly connector.

6. Sequence Diagram

Notation (Week 6): actor and objects across the top (name:Class), dashed lifelines, activation bars, numbered messages, solid arrow = synchronous call, dashed arrow = return, a temporary object (fv:FeatureVector) is created mid-scenario and destroyed with an X.

7. Communication Diagram

Notation (Week 6): same interaction as the sequence diagram, drawn free-form. Objects joined by links; numbered messages (1, 2, 3, 3.1, 3.3.1 ...), [guard] on 3.1 and * for iteration on 3.2.

8. Deployment Diagram

Notation (Week 6): 3D boxes for nodes with «device» / «server» stereotypes, nested nodes (execution environments), artifacts inside nodes, labelled communication paths (HTTPS, TCP/IP, SFTP).
